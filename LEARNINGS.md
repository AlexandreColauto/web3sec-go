- [20260908-i542] (tactic) Appending markdown plan chunks via `cat >>` merges the prior chunk's trailing `---` separator with the next chunk's `### Task N` heading (no newline) → grep -c '^### Task' undercounts and the plan looks incomplete. After EVERY multi-chunk append, repair with: replace lines starting `---### Task` → `---`, empty line, then the heading minus `---`. Then recount `^### Task` and scan for `Task 1[0-9].*Task` leftovers. Write each OpenVim/plan chunk with the `write` tool using a `const c = String.raw\`...\`` template, ESCAPING every backtick as `\`` (fences become `\`\`\`go`) — a single unescaped backtick (e.g. the token `\`*bytes.Buffer*\`` or `\`snap\`/init\``) throws a JS parse error ('Expected a semicolon' / 'Expected unicode escape'). ipython + Python is the fallback for content that keeps tripping the JS parser.
