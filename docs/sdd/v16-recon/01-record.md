## Traps (what a plan must not break)

1. **Byte-compat goldens.** stdout of `verify`/`audit`/`doctor` is byte-compared by the golden suites (docs/gates/P0..P4-gate.md) against the retired Python twin; `verifyLog` even keeps key order "contractual" (cmd_verify.go:265-273) and pushes extra text to *stderr only* (cmd_verify.go:277-286). Any output change must update the goldens + docs/gates together.
2. **Schema error strings are golden-pinned** — `internal/validation/schema_golden_test.go:236-246` asserts exact `model_request validation failed at ...` messages; adding schema keys can change error text.
3. **Audit section registry order** is registration order and load-bearing; `audit.RegisterAuditSection` panics on duplicates (audit.go:59-63). New sections must register without reordering the six P0 ones.
4. **`verify` is dual-purpose:** default branch = ledger verify_log (exit 1 silent on failure); flags (`--scaffold/--invariant/--exec/...`) = finding reproduction/harness. Don't repurpose the verb for model-stage checks — the Phase-1 out-of-set refusal belongs in the boundary/trajectory layer, not a new meaning for `verify`.
5. **Legacy unchained logs must still verify** — `VerifyLog` reports `legacy_unchained` and treats pre-chain events as acceptable (verifylog.go:21,496-497); don't hard-require `prev_hash` on old logs.
6. **Chain is a format check, not integrity** — the doctor.json repair-journal note (cmd_verify.go:277-286, verifylog boundary note) documents that a rewriter who recomputes hashes verifies green. Any new "recorded refusal" claim should cite the *event*, not trust the chain.
7. **failSilent contract:** `verify`/`audit` failures exit 1 with no further output after the report (cli.go:341-346, `failSilent` :364); `withErr` maps usage errors to exit 2 with the argparse-shaped usage block. New commands must keep this mapping or the golden exit codes break.
8. **Deterministic pins are environment hooks, not test-only:** `WEBV2_NOW`/`WEBV2_UUID`/`WEBV2_FINDING_IDS` are read in production code (id.go:21, main.go:155,174) and every golden step depends on their exact semantics (per-step seed so two `exec` calls can't mint the same EXEC-; verify-full.sh:170-186).
9. **Exit code 3 exists:** `run`'s halt path exits 3 (golden P3) while the spec text says 0/1/2 — CRITICAL_HUNTING_PLAN.md:0.2 already normalizes on 0/1/2/3; keep the documented contract and the code in sync before any Phase-1 exit-criteria claim.
10. **`preconditions` vs `assumptions` distinction** is schema-documented and test-enforced (finding.schema.json:240,278; validation/sweep_t35b_test.go:23-28 checks the schema description) — adding v1.6's enumerated precondition statuses must not blur it.
