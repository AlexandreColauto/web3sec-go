## Traps (things a plan must not break: existing tests, golden surfaces, deterministic pins, audit sections)

- **Determinism pins:** `WEBV2_NOW` / `WEBV2_UUID` clock/id pins (internal/snapshot/pin.go:39–41; internal/findings/storage.go:112; internal/costs/costs.go:38) — any new mint/id/telemetry write must route through `state.NowIso()`/`state.NewID` so the golden suite stays reproducible.
- **Byte-exact CLI surfaces:** every verb's help/usage and error strings are test-pinned (`mintHelp` "byte-exact" cmd_mint.go:24; `assumeUsage` "pinned byte-for-byte" cmd_assume.go:23; `ladder <action> failed:` exit-2 mapping cmd_ladder.go:61–72). Adding flags means updating the pinned help block and its test in the same change.
- **Mint idempotency is per (exec, type)** — cmd_mint.go:213–242; and a reused exec in a NEW attempt is refused by design (reproduction_attempt.go:289–300 "a re-run must be a NEW exec"). A maximization loop that re-cites execs will silently no-op.
- **Truncated capture refusal** (exec_evidence.go:181) and the capture-accounting honesty rule (cmd_exec.go:494–524): a maximization engine's output must stay under `output_capture.cap_bytes` or mint refuses; do not raise the cap to "fix" it.
- **EXEC ledger is the only door to E4+** (exec_evidence.go:17–19); `host-readonly` (and halmos/forge-fuzz/minicertora host profiles) can NEVER back E4+ (cmd_exec.go:375–380, profiles.go:26–33, exec_test.go:182 pins minicertora's exclusion from E4_PROFILES). A maximization loop must run engines under container/`fork-runner` profiles or its evidence is inert.
- **Ladder integrity laws** (maximization.go:6–13): a rung above base counts only when REPRODUCED with its own EXEC; disproof queues negative memory; the ladder closes with an explicit disposition (complete|waived), never silently open — `complete`/`waive` back the `maximal-exploitation` completion proof "every CONFIRMED finding maximized or waived" (internal/completion/proofs2.go:61). Don't add a terminal state that bypasses the disposition.
- **Golden harness files:** `internal/sequencepoc/testdata/driver_*.golden` pin the generated `cast call/storage` lines byte-exact (driver_runner.golden:110) — changing cast invocation shape requires regenerating goldens, and those scripts are the only sanctioned cast usage today.
- **Artifact registry invariants:** one row per path (cmd_artifact_register.go:13–24), empty files refused with no `--allow-empty` bypass (:28–34), kind enum comes from the schema document, not code (:37–45). Impact artifacts must register via `RegisterOrRefresh` or the citation/audit sections (internal/state/artifacts_citation.go, internal/audit/) diverge.
- **Append-only hash-chained ledger, one writer per campaign** (RUNBOOK:1849–1851; spec Part 8): no side-channel writes for loop state; every engine round must be a ledger event through the CLI/state layer.
- **Existing failure-classification semantics:** "logic" is the only class that argues the finding (envseam_classify.go:183–189) — a maximization `engine-failed` must NOT be mapped onto the existing `logic` class, or `webv2 classify`-driven fresh-context budgeting (cmd_budget.go / max_repro_attempts_per_finding, reproduction_attempt.go:62–66) will be distorted.
