## Traps (things a plan must not break)

- **cli.py-verbatim CLI contracts.** Many commands in this area are documented ports with pinned argparse-shaped errors and exit codes — `precondition` mutual-exclusion error text (`cmd_precondition.go:84-107`), `ladder`'s `ValueError/KeyError/RuntimeError → exit 2` mapping (`cmd_ladder.go:56-58`), `adjudicate` display defaults (`cmd_adjudicate.go:422`). Changing the `precondition` verb's flag grammar is a *new* surface, not an edit — its tests pin the current grammar.
- **`waiveStages` vocabulary pairing.** The waive stage list is pinned against the proof source by `TestWaiveVocabularyIsReadByProofs` (`cmd_waive.go:125-126`); a waiver landing on a stage no proof reads is refused at exit 2 (`:80-90`). Any new waiver subject must be added to **both** the vocabulary and the proof that reads it, or the test fails.
- **Floors immutability.** The built-in `CLASS_CONFIRM_FLOOR` table is never mutated by an override; overrides live in `state["floor_policy"]` and every set/clear is one hash-chained event cross-checked by `audit` (`internal/floors/floors.go:13-21`). A rubric-declared ceiling must follow the same data+event pattern, not edit defaults in code.
- **Live severity recompute is asserted, not accidental.** `SeverityFor` is recomputed at gate/report time by design; `finding.schema.json:1279` documents that the validated-risk score "the report and webv2 rank recompute it live so it never goes stale." Event-sourcing severity (§2.6) must not silently change what the `severity-floor` gate check (`gate_eligibility.go:108-119`) or the Immunefi "program severity" line (`immunefi.go:284-322`) render, or `internal/report/immunefi_test.go` and `internal/bounty/*_test.go` break.
- **Immunefi report golden surface.** Section order (`immunefiSections`, `immunefi.go:45`), the MISSING pre-submit checklist (`:152-186`), the reported-vs-computed severity line, and `no submission-ready findings` empty behavior (`cmd_report.go:54-56`) are pinned by `internal/report/immunefi_test.go`; the md report's gate re-run and status skip are pinned by `report_test.go`/`report_regression_test.go`.
- **Gate check IDs are a remediation-keyed API.** Every bounty-gate check (`severity-floor` = check5, `precondition-audit` = check10, `known-issue-check`, …) must have an entry in `BountyRemediation` (`internal/bounty/remediation.go:18`) or `gate explain` regresses; check names appear in report gate strings (`report_finding_section.go:200`).
- **Adjudication record invariants.** `evalscore.Record` refuses non-live finding ids, replaces prior rows, and unwinds state if the `eval.adjudicated` log fails (`internal/evalscore/adjudicate.go:278-295,347-352`); the `--json` projection key set is presence-gated and matched to the audit section (`cmd_adjudicate.go:466-532`) — new keys must be presence-gated the same way.
- **Determinism pins.** `WEBV2_NOW`/`WEBV2_UUID` (`internal/state/id.go:17-46`) drive golden-suite reproducibility; every new ledger event (severity, rescore, voucher, tranche) inherits this — never call `time.Now()`/uuid directly.
- **Schema version discipline.** Policy/records are validated with explicit versions (`validation.Validate(policy, "bounty_policy", 1)`); adding rubric keys means a schema bump plus the loaders in `internal/bounty/policy.go`, not a lenient read.
- **Audit sections are golden.** `audit`'s section set (snapshots, artifacts, unpriceable, sequence_coverage, adjudications) is asserted in `internal/audit/*_test.go`; the `stale-severity`/`stale-price` flags of §2.6 are additive sections, not mutations of existing ones.
- **Python truthiness helpers.** Field presence/absence semantics go through `pyTruthy*` (`pyTruthyInt64Only`, `pyTruthyBigNonEmpty`) — a new boolean schema key rendered in reports must pick the right helper or "absent vs false" diverges from pinned outputs.
