=====================================================================

processes themselves (lmwWorker / lockWorker), plus the parent test's own
start/return times. The instrumented test file was reverted with
`git checkout -- internal/state/processlock_r13_test.go`; nothing in the
committed tree carries the instrumentation.

Reading: every critical section is 7.2ms of real work (lock -> State -> edit ->
SaveState -> Log). The lock is then held for ~1.004s MORE by each worker, and
the next worker acquires it exactly one teardown later:

  worker 2 done 01.6357  ->  worker 4 locks 02.6400   (+1.0043s)
  worker 4 done 02.6493  ->  worker 3 locks 03.6522   (+1.0029s)
  worker 3 done 03.6619  ->  worker 1 locks 04.6683   (+1.0064s)
  worker 1 done 04.6765  ->  worker 5 locks 05.6816   (+1.0051s)
  worker 5 done 05.6900  ->  worker 0 locks 06.6992   (+1.0092s)

lmwWorker ends in os.Exit(0), so its `defer c.UnlockProcess()` never runs and
the kernel releases the flock only when the process dies. The ~1.004s between
"last write" and "next lock" is therefore process teardown under -race.

--- Run B: TestConcurrentLoggersKeepOneLedger (6 workers), -race — the control,
    because this worker does NOT hold the lock past its write (Log's own
    deferred unlock releases it):

worker diag (.scratch/r13diag/logger.txt):
worker-start       pid=956376 07:25:32.772157
worker-before-exit pid=956376 07:25:32.778994   (7ms of work)
... five more workers, all started within 5ms, all done within 112ms

parent test's view of the same worker (it reports when CombinedOutput returns):
DIAG logger worker 4 pid=956376 started=07:25:32.756607 returned=07:25:33.780988
elapsed=1.024382728s

Reading: 7ms of work, then 1.002s before the process is reaped. The teardown
cost is ~1.0s per process in this -race test binary, independent of the lock.
That is why the budget — not the lock hold — ran out in
TestConcurrentLoadModifyWritesLoseNothing: 6 workers serialize at ~1s each
because each holds the lock until death, and the sixth needs >5s.

Conclusion: the r13/r14/r15 fail-loud law was never violated. The 5s wall-clock
budget was being spent on race-detector teardown, so the fix scales the budget in
-race test builds only (commit 1130e324) and pins the production value with
TestLockBudgetMatchesBuild.
