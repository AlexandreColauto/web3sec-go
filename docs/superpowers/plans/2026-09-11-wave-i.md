**Comparator semantics (locked — these are the honesty constraints):**
- The scored universe is exactly the `held` slice `backtest.Run` already builds, AFTER Task 2's temporal/near-dup exclusions are applied (Task 2 owns exclusion; this task consumes the filtered set — if Task 2 is not yet merged when this task lands, the controller re-orders; do not reimplement exclusion here).
- A baseline LABELS each held-out case flagged / unflagged. It is then scored with the framework's only interval source, `wilson.Format`:
  - `recall` = anchored / n, where a case is "anchored" iff its `gold.outcome == "confirmed-exploitable"` (the SAME accepted-definition `backtest.Run` uses — do not introduce a second one).
  - `precision` = flagged-and-accepted / flagged.
- `always` — flags every held-out case. `recall: n/n`, `precision: <accepted>/<n>`. This is the floor any real detector must beat; it exists so a recall number can never be read without its price.
- `never` — flags nothing. `recall: 0/n`; `precision: 0/0 (95% CI n/a)` — that literal string is what `wilson.Format(0, 0, "precision")` already returns; print it, never a bare ratio and never a fabricated 0%.
- `slither` / `aderyn` — run the real binary ONCE per distinct resolved source root (the suite shares one root, so this is 1-2 invocations, not one per case), parse with Task 5's `ToPayloads`, and flag a case iff some admitted payload's file BASENAME equals the basename of one of that case's `gold.locations[].file`.
- **Root resolution (locked, no new flag):**
  - `code.repo` starting with `internal://` ⇒ tool root = the CLI `root` (the repo root the suite's `gold.locations[].file` paths are relative to).
  - `code.repo` an existing absolute directory ⇒ tool root = that directory.
  - anything else (a GitHub URL, `owner/name`, a commit-pinned external repo) ⇒ **not-computable**.
  - a case with an empty `gold.locations` ⇒ **not-computable** (no anchor to match a tool file against).
- **Not-computable is never a miss.** Each tool baseline prints `skipped: <k>/<n> cases (no local checkout)` when k > 0. Treating an uncheckable case as unflagged would manufacture a false-negative rate out of thin air — that is the exact failure mode this line exists to prevent.
- **Binary gate (fail-open, mirrors the sandbox probe):** `exec.LookPath(name)`; when the binary is absent the baseline prints one line, `baseline <name>: SKIPPED (<name> not on PATH)`, emits no recall/precision lines, and the command still exits 0. When the binary exists but fails or produces unparsable JSON on every resolved root, print `baseline <name>: SKIPPED (tool failed on <r>/<R> roots)` and exit 0. When it succeeds on some roots and fails on others: score over the computable cases, and add `tool errors: <r> roots` to the `skipped:` line.
- **Canonical order:** the block prints baselines in the FIXED roster order `always, never, slither, aderyn`, regardless of argv order — argv order is accepted by argparse but must never reach output (two runs with the same flag set print the same bytes).
- **Advisory only:** the block prints AFTER the existing `verdict:` line; it never changes the verdict, the exit code, or any earlier byte. `backtest.Run` itself is NOT modified — the CLI composes `Run`'s string with the baseline block.
