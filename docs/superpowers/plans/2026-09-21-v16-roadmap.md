# web3sec-go × framework-plan-v1.6 — Roadmap and Plan Split

> **For agentic workers:** this is the index, not a plan. Each numbered plan below is a
> standalone writing-plans document with its own TDD tasks. Execute one plan at a time.

**Goal:** close the gap between the shipped `webv2` control plane and the re-baselined
`framework-plan-v1.6.md` (the spec), one phase per plan, in the spec's own build order.

**Why a split.** The spec spans nine phases and five subsystems (record, evidence,
discovery/closure, adjudication, severity/policy/report, targeting/telemetry). A single
plan would be mostly fiction. Per `writing-plans`, each subsystem gets its own plan that
produces working, testable software on its own.

**Evidence base.** Six read-only recon reports measured the as-built state against the
spec: `docs/sdd/v16-recon/{01-record,02-evidence,03-discovery,04-adjudication,05-severity,06-targeting-telemetry}.md`.
Every "EXISTS/PARTIAL/ABSENT" claim below is sourced there with `path:line`. Re-run the
same six questions before trusting a status older than the last merge to `main`.

Dependencies: **P0a** first (small, and it converts a comment into a test before anything
is built near it) → **P0 ∥ P1** (the spec runs those two in parallel) → P2 → P3 → P4 → P5 → P6.
**P0b** has no phase: it runs whenever the Part 4 callers are cut, and is deliberately not on
the critical path.
P4 consumes P1's PoC tiers, `fork_dependence` and replay record, so P1 lands first.
P2/P3's exit criteria need P0's held-out targets; if P0 slips, the spec's own fallback
applies (a ScaBench held-out project satisfies the gate, substitution recorded).

**If you have one executor, run P1 before P0.** The spec's parallel split assumes two
people: P0 is operator tooling over external data (contest reports, mirrors, SHA resolution),
P1 is pure Go against this repo. With one executor the parallelism buys nothing, and P1 is
the plan that is written, self-contained and unblocks P4.

**P6 is deliberately a bag.** It is the only row here that is not a subsystem, and it should
shrink: everything in it that can be split out gets its own small plan rather than waiting
behind two phases of verification work. P0a is the first such split; the deletion of the
three quarantined packages is the next, and it lands with the callers rather than before them.

## 4. Constraints every plan inherits

- **Go floor** `go 1.26.2`, module `websec`, **stdlib only** — no new dependencies.
- **Asset manifest.** Any edit under `assets/` (schema, runbook, prompts, playbooks) needs
  `python3 scripts/sync-asset-manifest.py` in the same change or `assets.TestAssetPackManifest` fails.
- **Byte-pinned surfaces.** CLI help/usage/error text is asserted verbatim; gate check ids
  appear in `BountyRemediation`, `internal/orchestrator/testdata/oracles.json` and the
  report gate strings; `internal/cli/testdata/p3_args_golden.json` pins argv behaviour.
  Change them deliberately, never incidentally.
- **Ledger law.** Every mutation goes through `findings.SaveThenLog` or `campaign.Log`
  with exactly one named event, unwinding projection state when the log write fails.
- **Determinism pins.** `WEBV2_NOW` / `WEBV2_UUID` / `WEBV2_FINDING_IDS`; never
  `time.Now()` or a raw UUID in a new record.
- **Schema discipline.** `additionalProperties: false` everywhere; a new key means a
  schema edit plus `validation.Validate(v, name, 1)` on the write path.
- **Audit sections** append at the end of `internal/audit/sections/register.go`; never
  interleave with the ported Python order.
- **Tests** are plain Go, same package, `t.TempDir()` campaigns, no Docker, no network,
  no model. Full gate: `go test ./... -count=1`, then `scripts/verify-full.sh`.
- **Realism law.** A test that matches on a framework literal — an id shape, a status
  string, an enum member, a key name — must be built from a value the real producer
  emitted, never from a hand-written fixture. The P1 critical finding was an id-shape
  regex that matched nothing the framework mints; it passed every test because the
  fixtures used shapes that do not exist. Where two vocabularies must agree (the
  declaration's kinds and the keys the bundle walk derives from; a gate's literal pair
  and the schema enum behind it), pin them EQUAL to each other in a test that reads both,
  so they cannot drift apart silently.
- **One end-to-end branch test per plan.** Every plan adds at least one test that drives
  the real verbs in sequence — build state, run the work, then read it back through the
  audit — and asserts the joined-up result. The P1 "feed validated the declaration and
  never recorded it" defect was invisible to five scoped task reviews and visible only to
  the whole-branch review: scoped reviews structurally cannot see cross-task wiring.
- **A gate that ships red gets fixed or counted.** `scripts/verify-full.sh` and the
  pre-commit gate must be green before a plan's work starts; if a red is genuinely
  out of scope, record it in `docs/gates/` with a count that must not grow. A gate
  everyone has learned to wave through is worse than no gate. (P1 found two: the
  legacy fixture's capture-machine absolute path, and smoke expectations predating an
  evidence-floor rule. Both are fixed; the gate is green.)
- **D9 freeze.** The spec changes only in response to a measurement. When a plan's exit
  criteria run, record the measurement in `docs/gates/` and cite it in any spec change.

## 5. What to do next

1. **P0a** — quarantine the three Part 4 packages with an import-guard test (allowlist =
   today's 17 importers, asserted equal so it cannot grow silently) and a `DEPRECATED`
   header naming each one's importers. Small, mechanical, and it converts a note in §2 into
   something the build enforces.
2. **P1** (written, ready) — pure Go, unblocks P4, and its Step 0 re-verifies the four
   premises it rests on. Record the result in `docs/gates/v16-P1.md`.
3. **P0** — in parallel with P1 *only if* a second executor exists; otherwise after it.
4. **P0b** — delete the three packages once their callers are cut. It is a refactor, not a
   cleanup, which is why it is sequenced behind the work that removes the callers.

Write P2's plan when P1's exit criteria have run — the closure tier's design depends on how
the field-validation matrix actually behaves, and writing it before that measurement is
exactly the spec-iterating-faster-than-measurement failure D9 exists to stop.

**Staleness.** Every plan opens with its own Step 0 re-verification of the specific
`path:line` claims it depends on; §1's status map is only as good as the last merge to
`main`, and the six recon reports are dated evidence, not live state.
