## 3. What the P1 record set did not anticipate

**(1) The profile that can mint is not the profile the task named.** `host-readonly` cannot
back E4+ evidence; only `fork-runner` is in the eligible set. The task said 10a was offline and
needed "nothing but the pinned checkout and forge". It is not offline: the project's own five
tests are **fork tests** (`test/DebtManager.t.sol:51`), so reproducing them needs network, and
a networked run must be sandboxed. The container path worked first try — image present, uid
1000↔1000, container forge 1.8.1 identical to host, egress fine.

**(2) The E4+ gate models "reproduction" as a PASSING test, and this target's evidence is
negative.** Two independent rules enforce it: `ValidateExecRecord` requires
`exit_status == 0`, and `exec_output_problem` refuses any forge output showing a failing suite
— *"a failing test is not a reproduction"*. The Exactly vulnerability **is** the absence of a
guard: the fix commit's own tests fail 0/5 because `MarketNotListed` is never raised. So the
reproduction exits 1 and its suite fails, by construction, however correctly it is sandboxed.
**Absence-of-refusal evidence has no mintable path at any profile.** This is the finding that
matters, and it is not a bug in this target — it is a gap in the evidence model, which assumes
a reproduction demonstrates something happening rather than something failing to happen.

**(3) CONFIRMED is unreachable one layer earlier than the task assumed.** The task expected
the CONFIRMED *gate clause* to be the obstacle. It never ran: `HYPOTHESIS → CONFIRMED` is not
a legal edge — the path is `HYPOTHESIS → POSSIBLE → CONFIRMED` — and each hop carries an
evidence floor (`POSSIBLE` needs E2). At E0 the first hop is already refused
(`evidence level E0 < required E2 for POSSIBLE`). The transition table fires before any clause.

**(4) `FORK_RPC_URL` is not the variable this reproduction needs, and no record knows that.**
It was auto-injected as `http://host.docker.internal:8545` (a dead endpoint) and never
checked — preflight has no RPC probe. The run actually worked because the project's test reads
`vm.envString("OPTIMISM_NODE")`, which had to ride in as a plain `--env`. Every framework
diagnostic (`evidence-floor-unreachable`, the env doctor, `ContainerForkURL`) keys on
`FORK_RPC_URL` instead, so the variable that gates the checks and the variable that makes the
run work are different. The record carries both views: `environment.env_keys=["OPTIMISM_NODE"]`
against `container.env_keys=[FORK_RPC_URL, FOUNDRY_LINT_ON_BUILD, OPTIMISM_NODE]`.

**Minor.** `--workdir <host path>` bind-mounts read-write at `/wd` and is also the container
cwd; there is no container-path flag, and preflight validates only the host side, so the
profile's `filesystem: sandbox-tmp` label understates the bind. A refused mint still writes
`repro.attempt` + `repro.attempt_rolled_back` to the ledger — a refusal leaves audit residue
while the finding file stays untouched.

## 5. What this means for 10b

**10b's precondition is not met and cannot be met by re-running 10a harder.** It needs a
CONFIRMED finding; the path to CONFIRMED is blocked by (2) and (3) above, neither of which is
about effort, profile choice or RPC availability. Three honest routes, none of them taken here
because each is a decision rather than a step:

1. **Author a positive PoC** — a test asserting the drain *succeeds* against an
   attacker-supplied market. It would pass, so it would mint, and it would be a different
   artifact from the project's regression tests. This is the route that matches the gate's
   model, and it is the most work.
2. **Widen the evidence model** to admit negative evidence — a suite that fails *for the
   expected reason* is a reproduction of a defect whose signature is an absent refusal. This is
   a product change with real design weight, and it should be its own task with its own review,
   not a patch made mid-spike.
3. **Use a different target for the spike** — one whose reproduction is a passing test. This
   abandons the control target's main virtue (a real, cited, on-chain incident) in exchange for
   a precondition that is already satisfied.

Until one is chosen and recorded, **10b stays blocked**, and the honest statement of Phase 2 is
that its arithmetic half is test-proven while its extraction half has no confirmed finding to
run on.
